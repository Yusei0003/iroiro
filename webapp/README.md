# 広報取り込みアプリ

陸前高田市広報の取り込み・受給者名簿との照合・見出し案内・高田町8区のごみ収集日/分別早見表をまとめた、単体で動くWebアプリ。

**`koho-app.html` を開けば、そのまま(ネット接続なしで)動きます。** ブラウザ内の保存(localStorage)にのみデータが残り、外部には一切送信されません。

## 構成

```
webapp/
  src/template.html      アプリ本体のテンプレート(プレースホルダー入り)
  seed/                  アプリに埋め込む初期データ
    bunbetsu/*.json       ごみの分別区分(10区分)
    gomi-items.json        分別早見表の検索用品目インデックス
    koho-issues.json       取り込み済みの広報号の記録
    headlines.json         各号の見出し案内
    gomi-schedule.json     高田町8区のごみ収集日(収集日程表を取り込む前の予備・出し方の注意・問い合わせ先)
  vendor/pdfjs/           PDF読み取り用に同梱している pdf.js 一式(vendor、変更しない)
  vendor/fonts/           見出し用フォント(M PLUS Rounded 1c)を使う文字だけに絞ったもの+ライセンス(OFL)
  tools/fetch_fonts.py    vendor/fonts/ を作り直すスクリプト(ここだけインターネット接続が必要)
  build.py                上記を組み合わせて koho-app.html を生成するビルドスクリプト
  koho-app.html           配布用の完成ファイル(build.py の出力。手で編集しない)
```

## ビルド方法

```
cd webapp
python3 build.py
```

外部ネットワークへのアクセスは不要。`koho-app.html` が生成される。

`src/template.html` や `seed/*` を直したら、必ず `python3 build.py` を実行してから `koho-app.html` をコミットすること(koho-app.html は生成物なので、テンプレートやseedと食い違わないようにする)。

## データの更新

- **新しい号の見出し・ごみ収集日を追加したい場合**: `seed/koho-issues.json` `seed/headlines.json` `seed/gomi-schedule.json` に項目を足して再ビルドする。既存のエントリの書き方をそのまま真似れば形式は揃う。
- **分別区分・品目を増やしたい場合**: `seed/bunbetsu/*.json`(区分カード)と `seed/gomi-items.json`(検索用の品目)を編集する。出典は市ホームページ「家庭ごみ・資源」(まちづくり推進課生活環境係)。
- **受給者名簿・照合記録**: アプリの中でユーザーが登録するデータなので、このリポジトリには含まれない(ブラウザのlocalStorageにのみ保存される)。

## 照合のしくみ

- 氏名は、全角半角・カタカナ/ひらがな・旧字体や異体字(髙→高、﨑→崎、實→実、齋→斎 など)・「々」の違いをそろえてから突き合わせる。異体字の対応表は `src/template.html` の `VARIANTS`。
- 慶弔欄の「お悔やみ」は「氏名(NN歳・字名)」の形なので、氏名の直後の年齢と、名簿の生年月日から計算した発行日時点の年齢(±1歳)を比べて、次の3段階で表示する。
  - **年齢一致**(要対応)/ **要確認**(年齢の記載がない、または生年月日が未登録。要対応に含める)/ **別人の可能性**(年齢が合わない。要対応に含めない)
- 文字をほとんど読み取れないPDF(画像だけのPDF)や、慶弔欄の記載が見つからない号は、「該当なし」とせず「照合できていない」と表示し、紙面で確認するまでお知らせに残す。おしらせ版は慶弔欄がないため照合記録を残さない。
- 照合記録に残るのは名前が一致した方の情報だけで、広報の本文は保存しない。そのため、名簿に後から追加した方は過去の号とは照合されない(その号のPDFを選び直すと、照合記録だけを追加できる)。

## ごみの収集日程表の読み取り

- 「燃えるごみ収集日程表」(曜日 → 町名・行政区)と、「燃えないごみ・ペットボトル…」「空きびん」「新聞(チラシ)・雑誌・段ボール」の各収集日程表(行政区ごとに4月〜3月の日付)を、文字の位置から表として読み取る。表の左端の町名・曜日は何行かの真ん中に1回だけ書かれているので、見出しが各まとまりの中央に来るように行を区切って割り当てている。
- 対象の地区は `src/template.html` の `GOMI_AREA`(高田町・8区)。行政区の書き方(`6・8・9・11・18・19`、`５～１９`、`全行政区`)から8区を含む行を選ぶ。
- 読み取った日付は、表の「第n◯曜日」の決まりどおりか、( )付きの日は祝日のため土曜日に移った日かを確かめ、結果を保存前に表示する。
- 祝日(春分・秋分は計算式、国民の休日・振替休日を含む)は端末内で計算する。令和8年度の収集日程表の全セル(756件、うち祝日で移動した日49件)と一致することを確認済み。燃えるごみは祝日と年末年始(12/31〜1/3)を「収集なし」として次の収集日を出す。

## 見出し用フォントについて

`vendor/fonts/` には、M PLUS Rounded 1c(SIL Open Font License 1.1、`vendor/fonts/OFL.txt`)を、テンプレートと seed で使っている文字だけに絞った woff2 を置いている。build.py がこれを埋め込むので、オフラインでも同じ見た目になる。

テンプレートの見出し・ボタン・タブの文言を変えて新しい字が増えたら、`python3 tools/fetch_fonts.py` を実行してから再ビルドする(足りない字は端末の標準フォントで表示されるだけで、動作には影響しない)。

## pdf.js について

`vendor/pdfjs/` には以下の3ファイルを同梱している(npm の `pdfjs-dist@3.11.174` から取得したもの):

- `pdf.min.js` / `pdf.worker.min.js` — pdf.js 本体
- `Adobe-Japan1-UCS2.bcmap` — 日本語文字の字形表(これが無いと日本語が正しく読み取れない)

アプリ内でPDFを読み取る機能(号の自動判別・慶弔欄との照合・見出し候補の抽出)は、すべて端末内(ブラウザ)で完結する。PDFのファイルも中身も外部には送信されない。

pdf.js を更新する場合は `npm install pdfjs-dist@<version>` した上で、上記3ファイルを `vendor/pdfjs/` に上書きし、再ビルドして動作確認すること。

## 制約・注意点

- ごみの収集日は、年度初めに市が配る「収集日程表」のPDFを、アプリの「高田8区のごみ」タブで取り込む(1年分を保存し、月が変わると自動でその月・翌月の収集日を表示する)。今年度の表が未取り込みのときは、お知らせ欄とごみタブに表示される。3月15日以降は、翌年度の表の取り込みを予告する。
- 取り込み漏れのお知らせは、広報が「上旬に号・中旬におしらせ版」の月2回発行であることを前提に、先月と今月の分だけを確認している。
- 生年月日は和暦(`H12.3.7` `平成12年3月7日` 等)・西暦のどちらのCSVにも対応。Excel保存のShift_JIS CSVにも対応している。
